# D1 方向板（給 Brandon 挑）

三張靜態畫面，都用示範病例的真實數字（55 歲男、168 cm／65 kg、SCr 1.1→0.95、7 劑 1000 mg q12h 輸注 120 分、兩點濃度 24.6／11.8、CL 4.38、Vd 49.8、AUC₂₄ 457）。曲線是用這組參數算出來的（預測 24.7，實測 24.6；trough 11.8），和工具輸出一致。

**不變的前提**：左邊填資料（工作底稿，段落 01 到 06 照舊）、右邊看結果。三張的差別在右邊結果怎麼組織，以及一個「招牌」想法。

| 檔案 | 名稱 | 右區怎麼排 | 招牌想法 |
|---|---|---|---|
| `A.html` | 報告式＋目標帶尺 | 結論區（大數字）→ 目標帶尺 → 候選方案 → 曲線與時間軸 → 參數 → 注意事項 → 監測 → AI Prompt | AUC 目標帶尺：0–800 一把尺，綠框＝目標 400–600，現行處方與候選方案的位置一眼看到；候選方案表每列也有迷你尺 |
| `B.html` | 時間軸主導 | 全寬時間軸（曲線＋給藥／抽血／SCr 三條事件軌）放最上面，結論在它上方一行；下面左填右看 | 曲線與事件合成一條時間軸；點事件跳到左邊對應列並標亮（畫面上第 7 劑與第 1 筆濃度已標亮示意） |
| `C.html` | 儀表板 | 右區是一塊塊儀表板：結論＋尺、候選方案用同一把尺並排比較、曲線、參數、下次抽血 | 候選方案用長條在同一把 AUC 尺上比較；「下次抽血」用半衰期尺（1×t½ 到 5×t½）；左邊上方多一條「輸入完成度」 |

截圖在 `shots/`：每張各四個——桌機 1440 首屏（`*_desktop_fold`）、桌機整頁（`*_desktop_full`）、手機 390 首屏（`*_mobile_fold`）、手機整頁（`*_mobile_full`）。

手機版的做法三張相同：頂端「輸入／結果」切換、底部固定一條結論摘要（AUC 與是否達標）、第一屏看得到 AUC 與達標。

這些是方向板，不是成品：只有 HTML＋CSS＋少量切換用的 JavaScript，不含計算，也不連到 `index.html`。產生器在 `src/`：`boards_build.py` 輸出三個 HTML，`shoot.py` 用本機 Edge（無頭模式）產生截圖；先在 repo 根目錄開 `python -m http.server 8765`。手機截圖用 390 寬的 iframe 才是真正的 390 px 版面（無頭 Edge 視窗最窄約 500 px）。
